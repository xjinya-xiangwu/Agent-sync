# 家族 B：政企 AI 项目文档包 — 执行方案 v1.0

> 定位一句话：给政企 AI 项目乙方的投标与交付文档军火库——验收标准、方案书、POC 模板三件套。
> 系列建议名（可改）：「政企 AI 交付文库」

> 需求依据：2026 年政务/国企 AI 招标明显增长，采购标准从"参数竞赛"转向"合规性、可追溯性、实际业务效果"——评测与验收章节从加分项变成门槛项，而绝大多数中小供应商写不出这一章。

---

## 1. 受众画像与购买动机

| 人群 | 核心动机 | 对应 SKU |
|---|---|---|
| 中小软件公司售前/方案经理 | 投标：写出能过技术评审的 AI 方案书 | SKU2（方案书） |

## 2. SKU 明细（按生产顺序：SKU1 → SKU2 → SKU3）

### SKU1：AI 项目验收标准与评测指标模板（首发，通用性最强）

**为什么先做它**：甲乙双方都能用；制作最轻（纯方法论文档+模板表）；搜索需求最明确（"AI 项目怎么验收 / 大模型项目验收标准"）；且是 SKU2 方案书中评测章节的独立沉淀，生产上先写它、后复用进 SKU2。

**定价**：399 元个人版 / 999 元团队版（10 人内）。首发早鸟 299（前 30 份）。
**形态**：PDF/Word 主文档（80–120 页）+ 可编辑表格文件。

**目录结构**：

```
1. AI 项目验收方法论
   1.1 为什么大模型项目不能按传统软件验收（确定性差异、效果概率性）
   1.2 验收的三层结构：功能验收 / 效果验收 / 安全合规验收
   1.3 常见验收纠纷模式与规避（指标口径不清、测试集争议、试运行扯皮）
2. 指标体系模板（可编辑表格）
   2.1 效果类指标：准确率/召回率/F1 的定义口径、适用场景与陷阱；
       人工评分方案（评分维度设计、标注规范、评分员一致性要求）
   2.2 性能类指标：响应时间（分位数口径）、并发、吞吐、长稳
   2.3 安全类指标：内容安全测试集通过标准、越狱测试、敏感词误伤率
   2.4 业务类指标：任务完成率、用户采纳率、人工介入率、降本量化口径
3. 测试集构建规范
   3.1 测试集规模与分层（题型分层/难度分层/业务域分层）
   3.2 数据来源合法性（真实业务数据 vs 合成数据，权属边界）
   3.3 金标准（ground truth）的生成与仲裁流程
4. 验收流程模板
   4.1 分阶段验收设计（初验 / 试运行 / 终验，各阶段门槛与权重）
   4.2 问题分级标准（致命/严重/一般）与整改闭环 SLA
   4.3 验收报告模板（含签认页）
5. 甲方用法：需求书技术要求章节写法模板（怎么把评测要求写进招标文件，附两段示例条文）
6. 乙方用法：验收答辩准备清单 + 常见被挑战点与应答口径
```

**生产分工**：
- 人（W1）：定指标口径与"陷阱/纠纷模式"内容——这是全 SKU 的溢价核心，只有真做过交付的人写得出来（约 15h）。
- Agent（W1–2）：扩写说明文字、生成全部可编辑表格、构造示例数据（如一份 200 条分层的示例测试集结构）。
- 人（W2）：审改 + 补两段示例条文；排版出免费试读版（放"1.1 为什么不能按传统软件验收"整节）。

### SKU2：政企 AI 项目技术方案书模板（利润主力）

**定价**：499 元个人 / 1999 元团队；与 SKU1 组合 699（个人版组合价）。
**形态**：模板文档（Word，章节内含写法指引与占位示例）+ 一份完整填写的示例方案（60–80 页）+ 评标视角注解版。

**模板章节树（对标真实投标文件技术部分）**：

```
1.  项目理解与需求分析（招标文件响应式写法、需求拆解对照表模板）
2.  总体设计方案（总体架构图模板、技术路线选型论证、信创适配说明）
3.  模型与算力方案
    3.1 模型选型对比矩阵（通用基座/行业模型/开源部署，对比维度表）
    3.2 部署方案（本地化/私有云/信创环境的写法）
    3.3 算力配置估算表（并发 → 卡数 → 成本的推导模板）
4.  数据方案（数据治理流程、知识库建设工序、数据安全承诺写法）
5.  ★评测体系设计（离线评测集、指标体系、评测流程、效果承诺的安全写法——怎么写专业且不给验收挖坑）
6.  ★安全与合规章节（算法备案对照、生成式 AI 服务规定逐条响应、内容安全机制、等保适配）
7.  应用场景与功能设计（场景写法模板、功能清单矩阵）
8.  实施方案（项目组织架构、里程碑计划、甘特图模板）
9.  验收方案（引用 SKU1 的指标框架，分阶段验收设计）
10. 培训与运维服务（SLA 承诺的安全表述）
11. 风险分析与保障措施（含常见废标/低分风险清单）
12. 案例与团队（案例呈现写法：怎么把弱案例写出说服力）
```

**示例方案（虚构项目）**：「某省属能源集团知识管理与智能问答平台建设方案」——选能源集团是因为你做过国电网/国家管网/中核类项目的方案设计，行业细节还原度最高；文档内明确标注"虚构示例，结构与写法供参考"。

**评标视角注解版（最大差异化）**：在示例方案的关键章节插入批注框——"评委在这一节看什么 / 常见扣分点 / 加分表述示例"。来源限定于公开的评标办法通用条款 + 你的专业判断，不涉及任何在职机构未公开信息。

**生产分工**：
- 人（W3）：定章节树 + 评标注解要点（约 15h）。
- Agent（W3–4）：扩写模板占位内容、生成示例方案初稿（复用 SKU1 的指标表格 70%）。
- 人（W4–5）：审改示例方案，重点：架构叙述的行业真实感、评测章节数字自洽、评标注解的准确性。

### SKU3：POC 方案与评审模板（轻量补充款）

**定价**：299 元个人 / 699 元团队；三件套团队版 2999。
**形态**：PDF/Word（40–60 页）。

```
1. POC 方案书模板
   1.1 范围界定（★POC 最易失控点：明确纳入/排除清单模板）
   1.2 测试集约定（谁提供、多少条、怎么封存）
   1.3 环境与数据说明、时间计划
2. POC 评分表模板（甲方评审维度与权重设计）
3. POC 常见失败模式与规避（范围蔓延 / 数据未就绪 / 评测标准事后改）
4. 从 POC 到立项的转化要点（结果呈现的结构化模板）
```

**生产**：W5–W6，Agent 初稿 + 人 3 天审改（最轻的一个）。

## 4. 获客执行

**渠道优先级与动作**：

1. **知乎/公众号长文**（主力，吃精准搜索）：《政企 AI 项目怎么验收——大模型项目验收标准设计指南》《AI 项目投标方案里的评测章节怎么写》——这类内容的搜索者就是付款人。W2 起每两周 1 篇。
2. **售前/投标社群**：知识星球上的售前星球、QQ/微信投标群；动作不是发广告，而是用免费试读版 + 回答群内 AI 项目问题建立专业人设，两周后发产品。首批目标进入 3–5 个群。
3. **标书代写服务商分销**：谈判要点——给 30% 佣金，他们接 AI 项目标书单时把 SKU2 作为"加速包"推荐；他们的客户付 5000+ 代写费，699 的模板组合是天然 upsell。目标签 2–3 家。B2B2C 是本线最重要的杠杆。
4. **视频号/B 站**（低频人设）：每月 1–2 条"政企 AI 落地"讲解，长期建立可检索的专业身份。
5. **公开案例引流**（衔接家族 C）：每个 SKU 配一篇脱敏复盘案例（基于公开招标文件与中标公告的专业重构，明确标注），文末挂产品。

**交付与收款**：B 端要发票的概率不低——个人主体初期用平台代收（闲鱼企业也可购买）+ 无发票低价策略；若团队版订单出现对公/发票需求，用灵活用工/个体户开票通道解决，W6 前确认方案。

**漏斗**：知乎长文/社群答疑 → 免费试读版 → 299/399 个人版 → 999–2999 团队版 → 分销商批量授权。

## 5. 验证指标与淘汰信号（W6 复盘）

继续信号：
- SKU1 ≥ 15 单（含 ≥ 2 个团队版）；
- 至少签下 1 家标书代写分销；
- 知乎两篇长文合计带来 ≥ 500 次商品页访问。

淘汰/收缩信号：
- 咨询主要诉求是"能不能帮我们写这个标/陪这个项目"（> 50%）→ 不转服务（违反零定制约束），改为把模板批量授权给标书代写商，走 B2B2C；
- 集中问"XX 省格式能不能适配"（> 30%）→ 出省份/行业变体扩展包（+199），不做单项目适配。

## 6. 合规红线（本线尤其重要）

1. 所有内容基于公开法规、公开招标文件与个人通用方法论；不使用现任或前任雇主的内部文档、评审细则、客户材料。评标注解限定为"公开评标办法通用条款 + 个人专业判断"。
2. 示例方案为虚构项目并显著标注；不含任何可识别的真实项目信息。
3. 不承诺中标；商品页明示"文档模板与写法参考，不含代写与咨询服务"。
4. 发布前做一次与现任职务的利益冲突自查（本线内容与 AI 安全主业相邻，SKU1 的安全类指标章节尤其过一遍）。
